# Спринт 5. Аналитика PostgreSQL и документная модель MongoDB

Ветка `lab5` (от `api`): SQL-каталог в `lab5/sql`, документная часть — в Go REST API (`internal/…`), документы — в `docs/lab5/`.

## 1. SQL-каталог (8 запросов)

Q1–Q5 из ЛР3 дополнены тремя запросами: **Q6** (ранжирование `RANK() OVER (PARTITION BY …)`, CTE), **Q7** (`LAG()`, CTE), **Q8** (накопительный `SUM() OVER` и скользящее среднее `AVG() OVER (ROWS 6 PRECEDING)`, CTE, календарь). Выполняются на 3 млн рейсов за 9–780 мс. Для каждого запроса указаны бизнес-вопрос, параметры и пример результата — `sql-catalog.md`.

| Требование | Выполнено |
|---|---|
| ≥ 3 с агрегатами | 7 запросов |
| ≥ 3 с оконными функциями | Q6, Q7, Q8 |
| ранжирование / LAG / накопительный и скользящий | Q6 / Q7 / Q8 |
| ≥ 2 с CTE или подзапросами | Q6, Q7, Q8 |
| ≥ 5 с соединением нескольких таблиц | Q2, Q3, Q4, Q6, Q8 (3–4 таблицы) |

**Дополнительно:** автоматическая проверка SQL (`make sql-check`): тестовая БД, результаты всех восьми запросов сверяются с эталонами, посчитанными вручную до запуска (проверка сама проверена на испорченном эталоне). В зачёт трёх дополнительных пунктов она не идёт (см. раздел 7).

## 2. Владение данными

PostgreSQL — источник истины для пользователей, маршрутов, остановок, автобусов, рейсов, инцидентов (ограничения, транзакции, аналитика). MongoDB владеет телеметрией, журналом событий рейса, заметками расследования и гибкими атрибутами остановок; для остановок и состава маршрутов хранит проекцию (источник истины — PostgreSQL). Правила связи между хранилищами и список задач, где документная модель выигрывает, — `data-ownership.md`.

## 3. Коллекции

| Коллекция | Документ | Связь |
|---|---|---|
| `telemetry_buckets` | точки одного автобуса за час (корзина) | 1:N встроенные точки; ссылка на автобус |
| `trip_journals` | журнал событий рейса | 1:N встроенные события; `_id` = рейс |
| `incident_cases` | карточка расследования | ссылки на рейс, автобус, маршрут, людей; встроенные комментарии |
| `stop_points` | остановка: проекция + гибкие атрибуты + гео-точка | **M:N** с маршрутами (`route_ids`) |
| `route_profiles` | состав маршрута | **M:N** с остановками (`stops[].stop_id`) |

Диаграмма и индексы — `collections.md`, словарь полей — `dictionary.md`.

## 4. Embedding и reference

Встроены те данные, что принадлежат родителю, читаются вместе с ним и растут только в конец (точки корзины, события журнала, комментарии). Ссылкой хранятся данные, которые живут своей жизнью или принадлежат PostgreSQL (рейс, автобус, маршрут, пользователи; остановка, общая для десятков маршрутов). Обоснование по чтению, обновлению и размеру — `embedding-vs-reference.md`.

**Эксперимент (рост встроенного массива).** Жёсткий предел документа — 16 МиБ, для нашего события ровно 141 918 событий (на одно больше сервер отклоняет). Практическая граница — около 9 000 событий (~1 МиБ): дальше чтение целиком заметно дорожает (50 000 событий — 51 мс, 100 000 — 97 мс). Выбранные границы в приложении (журнал 500 событий, корзина 720 точек, 200 комментариев) лежат с большим запасом.

## 5. CRUD, валидация и бизнес-правила

CRUD реализован в Go REST API (те же слои и тот же JWT, что и остальной API): 20 эндпоинтов, матрица и примеры — `crud.md`. Схема валидации `$jsonSchema` (`strict` + `error`) применяется при старте и проверяет типы, обязательные поля, диапазоны и правила формы; бизнес-правила обеспечиваются схемой, атомарными условиями записи и проверками сервиса — `validation.md`. Среди них: широта и долгота в пределах (BR-10, BR-11), время измерения обязательно (BR-12), телеметрия только для существующего автобуса (BR-09), хронология событий журнала, закрытая карточка не принимает комментариев, карточку можно закрыть только при закрытом инциденте в PostgreSQL.

## 9. Ограничения

- MongoDB — одиночный узел: многодокументных транзакций нет, консистентность между документами обеспечивается порядком идемпотентных шагов (ADR-006, ADR-010).
- Проекция остановок создаётся явно администратором; при расхождении с PostgreSQL верна запись в PostgreSQL.
- Стратегия версий документов описана, но не применялась: пока одна версия схемы.
- Redis (текущее положение автобусов) в этой работе не реализуется.
